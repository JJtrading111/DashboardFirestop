# Bouwberichten Dashboard integration

Locate the application repository by `server.mjs`, `public/model.mjs`, and `package.json` (`bouwberichten-dashboard`). In this desktop workspace it is under `work/bouwberichten-railway`.

The first target is Bouwberichten.nl. Its project overview, authenticated pages, selectors, and data API have not yet been validated. Request the overview URL and whether login is required when that information is missing. Do not infer a working project scraper from the public homepage.

Read `docs/SCRAPING_SETUP.md` in the application repository for the API contract and setup steps. Use `scripts/import-leads.mjs` for importing validated JSON. Its dry-run mode prepares batches without transmitting data. Source IDs are immutable; copy the endpoint for the existing Bouwberichten.nl source from the dashboard's **Import instellen** dialog, rather than identifying a source only by display name.

The import endpoint is `POST /api/import/sources/:sourceId/leads`. It uses a source-specific bearer token generated by a hoofdbeheerder. It does not use the administrator password, browser session, or CSRF token. Rotation invalidates the previous import token; pausing, revoking, or deleting the source must stop imports.

Use stable external project IDs or canonical detail URLs. Repeated imports must update the same central lead, preserve its creation date and historical reporting cohort, and preserve every company's notes, ownership, Kanban state, calls, callbacks, and conversion flags. Do not assign imported leads to the importing administrator. Missing phone or email values remain empty.

Keep extraction code and import credentials outside the dashboard browser. The dashboard process is the only writer of its SQLite volume. A scraper sends records through the import endpoint; it never edits the production database directly.

Before the first real import, use a small validated batch and repeat it to verify duplicate prevention. Update one project and check that its existing company follow-up remains. An empty or failed scrape must not delete existing leads. Read-only discovery and local fixtures do not establish that a production connector is active.
