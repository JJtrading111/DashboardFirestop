# Bouwberichten Dashboard integration

Locate the application repository by `server.mjs`, `public/model.mjs`, and `package.json` (`bouwberichten-dashboard`). In this desktop workspace it is under `work/bouwberichten-railway`.

The first target is Bouwberichten.nl, which requires login. The signed-in project list and detail pages have been inspected. The implementation in `scraper/bouwberichten-api.mjs` translates explicit filters and maps the code-derived portal API contract; the auth/worker modules implement a fresh Playwright login and bounded serial extraction. Unit tests use fixtures. Do not claim real API authentication or extraction has succeeded until an actual source proof has passed.

The user supplied the explicit filter URL `https://portal.bouwberichten.nl/projecten#projects%5Bfilters%5D%5BlastPublishedAt%5D%5Bstart%5D=2025-12-31T23%3A00%3A00.000Z&projects%5Bfilters%5D%5BconstructionPhase%5D%5B%5D=Gegund`. It means phase Gegund with publication from 01-01-2026 in Europe/Amsterdam. The signed-in page showed 1,094 results on 2026-11-24. This is a publication filter, not necessarily an award-date filter. Do not substitute `sourceUpdatedAt` for publication date.

Each selection can be a separate source with `provider: 'bouwberichten'` and its own `filterUrl`, import endpoint, token, pause setting, and run history. Read its stored explicit filter parameters. An ID-only saved-search link is insufficient: the portal can reuse its prior selection. Keep OAuth/login URLs and session credentials out of source configuration.

Read `docs/SCRAPING_SETUP.md` in the application repository for the API contract and setup steps. Use `scripts/import-leads.mjs` for importing validated JSON. Its dry-run mode prepares batches without transmitting data. Source IDs are immutable; copy the endpoint for the intended filter source from the dashboard's **Import instellen** dialog, rather than identifying a source only by display name.

External import uses `POST /api/import/sources/:sourceId/leads` with a source-specific bearer token generated by a hoofdbeheerder. It does not use the administrator password, browser session, or CSRF token. The bundled Railway worker instead claims a temporary source-scoped job through `/api/scraper/claim` using `SCRAPER_WORKER_TOKEN`; `/api/scraper/jobs/:id/batch` validates the lease and feeds the same import contract. No raw import token is needed by that worker. Rotation invalidates the previous external import token; pausing, revoking, or deleting the source cancels scraper jobs and stops imports.

Use the same stable external project ID across all Bouwberichten filter sources. Their imports share one central lead with multiple source memberships; generic sources remain independent. Repeated imports must preserve the lead's creation date and historical reporting cohort, and every company's notes, ownership, Kanban state, calls, callbacks, and conversion flags. Memberships are historical, not removed when a later filtered result omits a project. Existing duplicate records are not mass-merged. Do not assign imported leads to the importing administrator. Missing phone or email values remain empty.

Keep extraction code and machine credentials outside the dashboard browser. A chief can submit a source login in **Automatisch ophalen**; the server stores it with AES-256-GCM and the Railway-only encryption key. Neither browser state nor exports receive the stored password. The worker receives credentials only for a leased job over HTTPS and never saves tokens, browser profiles, or screenshots. Extra login verification stops the job. The dashboard is the only writer of its SQLite volume; the worker never mounts it.

Connection queues a proof of at most five projects. Full extraction (at most 5000, no silent truncation) and the optional 24-hour schedule require a successful proof. The worker polls every 15 seconds, paces source requests by one second, and stops a job after an hour. Changing filters resets proof and cancels jobs; disconnecting erases the stored login. Review `docs/SCRAPING_SETUP.md` for precise setup and limits.

Before the first real import, use a small validated batch and repeat it to verify duplicate prevention. Update one project and check that its existing company follow-up remains. An empty or failed scrape must not delete existing leads. Read-only discovery and local fixtures do not establish that a production connector is active.
