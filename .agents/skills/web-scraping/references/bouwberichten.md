Locate the application repository by `server.mjs`, `public/model.mjs`, and `package.json` (`bouwberichten-dashboard`). In this desktop workspace it is under `work/bouwberichten-railway`.

The first target is Bouwberichten.nl, which requires login. The signed-in project list and detail pages have been inspected, but automated extraction, the API response contract, and persistent scraper authentication have not been validated. Do not infer a working connector from this browser inspection.

It means phase Gegund with publication from 01-01-2026 in Europe/Amsterdam. The signed-in page showed 1,094 results on 2026-11-24. This is a publication filter, not necessarily an award-date filter. Do not substitute `sourceUpdatedAt` for publication date.

Each selection can be a separate source with `provider: 'bouwberichten'` and its own `filterUrl`, import endpoint, token, pause setting, and run history. Read its stored explicit filter parameters. An ID-only saved-search link is insufficient: the portal can reuse its prior selection. Keep OAuth/login URLs and session credentials out of source configuration.

Read `docs/SCRAPING_SETUP.md` in the application repository for the API contract and setup steps. Use `scripts/import-leads.mjs` for importing validated JSON. Its dry-run mode prepares batches without transmitting data. Source IDs are immutable; copy the endpoint for the intended filter source from the dashboard's **Import instellen** dialog, rather than identifying a source only by display name.

The import endpoint is `POST /api/import/sources/:sourceId/leads`. It uses a source-specific bearer token generated by a hoofdbeheerder. It does not use the administrator password, browser session, or CSRF token. Rotation invalidates the previous import token; pausing, revoking, or deleting the source must stop imports.

Use the same stable external project ID across all Bouwberichten filter sources. Their imports share one central lead with multiple source memberships; generic sources remain independent. Repeated imports must preserve the lead's creation date and historical reporting cohort, and every company's notes, ownership, Kanban state, calls, callbacks, and conversion flags. Memberships are historical, not removed when a later filtered result omits a project. Existing duplicate records are not mass-merged. Do not assign imported leads to the importing administrator. Missing phone or email values remain empty.

Keep extraction code and import credentials outside the dashboard browser. The dashboard process is the only writer of its SQLite volume. A scraper sends records through the import endpoint; it never edits the production database directly.

Before the first real import, use a small validated batch and repeat it to verify duplicate prevention. Update one project and check that its existing company follow-up remains. An empty or failed scrape must not delete existing leads. Read-only discovery and local fixtures do not establish that a production connector is active.
